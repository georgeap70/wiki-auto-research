# Self-Optimizing Multi-Agent Systems for Deep Research

**Paper:** [arXiv 2604.02988](https://arxiv.org/abs/2604.02988) — April 3, 2026
**Workshop:** Conversational Search for Complex Information Needs, ECIR 2026
**Institution:** Zeta Alpha, Amsterdam
**Authors:** Arthur Câmara, Vincent Slot, Jakub Zavrel

---

## What Is Being Solved

Multi-agent Deep Research systems rely on **hand-engineered system prompts** for all four agent roles (orchestrator, reader, aggregator, writer). When underlying models change or domains shift, prompts must be redesigned manually. The paper investigates whether automated prompt optimization — textual gradient descent (TextGrad) and evolutionary (GEPA) methods — can match or outperform expert-crafted prompts without human intervention.

This is prompt optimization as a form of self-improvement: treating system prompts as learnable parameters that the system refines through its own experience.

---

## Multi-Agent Architecture

A four-role pipeline for iterative multi-document retrieval and synthesis:

**Orchestrator Agent:** Receives user query → produces initial plan and task list (each task contains a search query + extraction instructions) → analyzes collected evidence after each retrieval round → decides to issue more tasks or proceed to writing.

**Reader Agents (parallel workers):** Retrieve large document batches (webpages, PDFs) → extract task-relevant evidence per orchestrator instructions → output citation-backed snippets with document IDs in square brackets. Designed for high recall via parallel inspection.

**Aggregator Agent:** Combines reader outputs for a given task → produces a mini-report → de-duplicates overlapping evidence, reconciles conflicts, discards weak evidence. Preserves citation identifiers.

**Writer Agent:** Generates final long-form report from aggregator mini-reports → inserts citations → creates unified bibliography.

Citation chain: Reader → Aggregator → Writer preserves URL-hash identifiers throughout.

---

## What Is Being Optimized

The **system prompts** of all four agents: C = {c_orchestrator, c_reader, c_aggregator, c_writer}.

Optimization target: answer quality on PhD-level CS queries, as measured by rubric-based LLM evaluation.

Round-robin agent optimization: one agent's prompt is updated per optimization step, cycling through all four.

---

## Prompt Optimization Methods

### TextGrad (Textual Gradient Descent)

Treats prompts as "learnable parameters" analogous to neural network weights:

1. Select current best system (greedy hill-climbing on dev split)
2. Sample mini-batch of training queries
3. Generate answers with current prompts
4. Evaluate answers against rubric → produce textual "loss" (per-sample critique of the prompt)
5. Aggregate losses across batch → textual "gradient" (improvement suggestions)
6. LLM optimizer updates prompt based on gradients
7. Repeat up to 10 epochs

Greedy selection → always works from a single best candidate. Simple but risks local optima.

### GEPA (Genetic-Pareto)

Evolutionary prompt optimization — maintains a **population** of prompt candidates:

1. Prune strictly dominated candidates (those not best on any query)
2. Sample candidates with probability proportional to Pareto "support" (frequency on the Pareto frontier)
3. Generate agent-specific feedback for each batch query
4. Use feedback to generate new prompt C'
5. Discard C' if it doesn't improve over C on the batch (patience: 2 consecutive non-improving rounds)

Key distinction from TextGrad: **diverse population + Pareto selection** vs. single-candidate greedy hill-climbing. GEPA with a task-specific meta-prompt significantly outperforms default GEPA — prompt engineering of the optimizer matters.

## Feedback Signals

- **LLM-as-judge rubric evaluation:** each answer scored against PhD-expert rubric criteria
  - Rubric-specific score: 60% of total (each item scored 0–10, normalized to [0,1])
  - Expertise alignment: 10%; citation coverage: 20%; excerpt presence: 10%
- **Textual "loss":** per-sample critique of the current prompt generated by the optimizer LLM
- **Textual "gradient":** aggregated improvement suggestions across a mini-batch

See [[concepts/feedback-signals]] — this is a case where the feedback signal is itself LLM-generated text, not a ground-truth scalar.

## Key Results

**Dataset:** ScholarQA CS subset — 109 PhD-level CS query-rubric pairs (29 train, 50 test, 30 dev)
**All agents and judges:** GPT-4.1-mini; mini-batch size 3; budget cap $50

| Optimizer | Minimal Prompt | Minimal + Optimizer | Expert Prompt | Expert + Optimizer |
|-----------|----------------|--------------------|--------------|--------------------|
| TextGrad | 0.513 | 0.654 | 0.667 | 0.672 |
| GEPA (default meta-prompt) | — | 0.685 | — | 0.670 |
| **GEPA (custom meta-prompt)** | — | **0.705** | — | **0.701** |
| OpenAI optimizer | 0.583 | 0.583 | 0.667 | 0.667 |

Key takeaways:
- **GEPA custom (minimal start) = 0.705** — best result overall, beats TextGrad starting from expert prompts (0.672)
- **TextGrad on minimal prompt:** +0.141 gain (0.513 → 0.654) — large improvement from near-zero
- **TextGrad on expert prompt:** only +0.005 — diminishing returns; expert prompts already capture most value
- **OpenAI optimizer:** zero improvement in both regimes — surprising null result
- **GEPA custom vs. GEPA default:** +0.020–0.031 — task-specific meta-prompt for the optimizer matters significantly
- Starting from minimal prompts, automated optimization can reach or exceed expert prompt quality

## Key Terms

- **Deep Research system:** multi-agent architecture for iterative multi-document retrieval and synthesis
- **TextGrad:** treating prompts as learnable parameters; LLM-generated critiques as textual gradients
- **GEPA (Genetic-Pareto):** evolutionary prompt optimization with Pareto-frontier candidate selection
- **Textual gradient / textual loss:** LLM-generated feedback used as gradient signal for prompt updates
- **Round-robin agent optimization:** cycling through agents one at a time per optimization step
- **ScholarQA CS subset:** benchmark dataset (109 PhD-level CS query-rubric pairs)
- **Pareto support:** frequency on Pareto frontier, used as sampling weight in GEPA
- **Darwin-Gödel Machine:** referenced theoretical ideal of full self-modifying agents
- **Deep Research Gym:** third-party evaluation infrastructure with FineWeb index
