# Feedback Signals

One of the most consistent findings across this literature: **rich diagnostic feedback produces substantially better self-improvement than scalar reward signals**.

## Scalar Feedback

A scalar signal tells the system *how much* it failed:
- Task pass rate: 0.56
- Win rate: 43%
- Loss value: 2.34

This is useful for gradient descent and simple threshold gating, but it provides no information about *why* failure occurred or *where* to look for fixes.

## Rich Diagnostic Feedback

Rich feedback tells the system *why* it failed and *what specific conditions* produced the failure:
- Full execution traces
- Compiler errors with line numbers
- Profiler output (where time was spent)
- Test case input/output pairs showing the failure
- Environmental feedback (which action was illegal, why)
- Source code of the failing component

### Named Concepts

**Actionable Side Information (ASI)** — [sources/optimize-anything](../sources/optimize-anything.md)'s formalization. ASI is any structured diagnostic information that can directly inform the next proposal. The key word is "actionable": the information is specific enough that a proposer can read it and identify what to change.

**Execution traces** — [sources/meta-harness](../sources/meta-harness.md) provides the optimizer with complete traces (up to 10M tokens). The optimizer can follow the execution path of a failure to its source in the harness code.

**Environmental feedback** — [sources/autoharness-arxiv](../sources/autoharness-arxiv.md) uses the environment's own validation signals (illegal move detection) to drive iterative constraint code synthesis.

**Failure mining** — [sources/auto-harness](../sources/auto-harness.md) extracts failures from production execution traces, clusters them by root cause, and converts clusters into eval cases.

**Analyzer distillation** — [sources/asi-evolve](../sources/asi-evolve.md) introduces a dedicated Analyzer agent whose sole job is to compress multi-dimensional experimental output (benchmark scores across 10+ datasets, logs, traces) into a compact, decision-oriented report before storing it in the database. This is feedback compression: the Analyzer interprets *why* a result happened, not just *what* the result was. Without it, the context window of subsequent iterations would be dominated by raw experimental noise.

**Qualitative shared notes** — [sources/coral](../sources/coral.md) agents write freeform markdown notes about what they tried, why it failed or succeeded, and what they hypothesize. Other agents can read these notes before making proposals. This is *human-readable* rich feedback: not structured traces but natural-language analysis accumulated across the population.

**Textual gradient / textual loss** — [sources/deep-research](../sources/deep-research.md) generates LLM-as-judge critiques of the current prompt (textual loss) and aggregates them into improvement suggestions (textual gradient). The feedback is prompt-specific and generated by an LLM, not by test infrastructure.

**Cross-trace pattern compression (RLM)** — [sources/halo](../sources/halo.md) uses a Recursive Language Model specialized for trace analysis to reduce many production traces (OpenTelemetry-collected) into a finite-length diagnostic report. The RLM's job is to surface *systemic* failure patterns (hallucinated tool calls, refusal loops, redundant arguments) that only emerge across many runs. This is feedback compression at a different scale than [ASI-Evolve's Analyzer](../sources/asi-evolve.md): ASI-Evolve compresses *experimental output*; HALO compresses *production execution histories*.

**Peer judgment via blind tournament** — [sources/autoreason](../sources/autoreason.md) uses fresh, context-isolated judges that rank candidate outputs via Borda count. The signal is *which output is preferred by independent voters*, not *what specifically is wrong with this output*. This sidesteps the prompt-bias problem (asking a model to critique reliably hallucinates flaws) by replacing critique with comparison.

**Rejected-edit buffer (negative signal)** — [sources/skillopt](../sources/skillopt.md) retains *failed* candidate edits as explicit negative examples for the optimizer. Most systems discard rejected proposals; SkillOpt treats them as a second persistent signal source — structurally analogous to hard-negative mining in contrastive learning. Combined with separate success/failure batch analysis, this gives the optimizer dense information about *what not to try* alongside the usual "what to try next" signal.

**Evidence-bounded feedback contract** — [sources/rlm-gepa](../sources/rlm-gepa.md) makes the rich-feedback principle into an explicit design constraint: *"optimization quality is bounded by the evidence your metric returns."* Effective feedback should *name specific failures* (missing findings, unsupported claims, wrong cells/clauses) but **not** prescribe text rewrites. This is the same principle as ASI, sharpened into a contract: the metric authors a *failure description*, the proposer authors the *fix*. Prescriptive metrics ("the prompt should say X") collapse the optimizer/target separation and tend to overfit.

**Declared optimization context (AgentSpec)** — [sources/rlm-gepa](../sources/rlm-gepa.md) introduces `AgentSpec` as a typed companion to the trace-level feedback: a structured description of *what's in-scope* for the optimizer (use cases, runtime affordances, scoring methodology, counterfactual axes for generalization). Most prior systems leave this context implicit, forcing the proposer to infer it from traces alone. AgentSpec treats it as a first-class input — a different category of feedback than "this run failed because X," more like a standing brief on the project.

**Between-round cross-cutting scans** — [sources/evo](../sources/evo.md) runs RLM-inspired scan subagents between rounds of its tree search: they read trace batches in parallel and surface *gate-failure intersections* (which gates tend to fail together) and *shared root causes across traces*. Findings land in shared state for the next round. This is feedback compression at yet another scale — between [ASI-Evolve's](../sources/asi-evolve.md) per-experiment Analyzer and [HALO's](../sources/halo.md) production-traffic RLM — and is distinguished by being a *standing phase* of the loop rather than an analyzer that runs at the end. The signal explicitly targets *systemic* failure patterns over the population of branches, not per-experiment diagnosis.

**Discarded-hypothesis store (negative-direction signal)** — [sources/evo](../sources/evo.md) keeps *discarded hypotheses* in shared state, readable by future subagents at startup. Conceptually parallel to [SkillOpt's](../sources/skillopt.md) rejected-edit buffer, but at the granularity of *experimental directions* rather than text edits: future subagents see "this approach was tried and shelved" alongside "this approach worked." Most systems retain only successful branches; treating negative experimental results as a first-class signal is unusual.

## Why Rich Feedback Wins

1. **Targeted proposals**: When the optimizer knows *where* a failure originated, it proposes targeted fixes rather than random perturbations
2. **Faster convergence**: Fewer iterations needed because each proposal is better-informed
3. **Avoids proxy overfitting**: Scalar metrics can be gamed; rich traces expose whether the fix is genuine
4. **Enables diagnosis of novel failures**: Scalar signals only confirm that a failure occurred; traces allow identifying never-before-seen failure modes

## Trade-offs

| | Scalar | Rich |
|--|--------|------|
| **Cost** | Low | High (tokens, compute) |
| **Proposal quality** | Lower | Higher |
| **Convergence speed** | Slower | Faster |
| **Scalability** | High | Limited by context window |
| **Infrastructure** | Simple | Requires trace collection |

The scalability concern is real: [sources/meta-harness](../sources/meta-harness.md)'s 10M token context approach works now but may hit limits as systems grow. This is an open research question.

## Feedback at Different Time Horizons

A useful distinction that emerges from newer systems: feedback can operate at the **iteration level** (informing the next proposal) or at the **session level** (accumulated across many iterations into persistent knowledge).

- Iteration-level: execution traces ([sources/meta-harness](../sources/meta-harness.md)), benchmark scores ([sources/asi-evolve](../sources/asi-evolve.md)), grader feedback ([sources/coral](../sources/coral.md))
- Session-level: learnings.md ([sources/auto-harness](../sources/auto-harness.md)), Cognition Base ([sources/asi-evolve](../sources/asi-evolve.md)), Notes/Skills ([sources/coral](../sources/coral.md))

See [concepts/knowledge-accumulation](knowledge-accumulation.md) for how systems structure session-level feedback into reusable knowledge.

## Capability Isolation as an Alternative to Signal Richness

**TRACE** ([sources/trace](../sources/trace.md)) offers a third approach distinct from both rich traces and credit assignment. Rather than making the global signal richer (traces) or redistributing it across time (credit assignment), TRACE **decomposes the global sparse signal into many locally dense signals**.

The mechanism:
1. Contrast successful and failed trajectories on the target environment to diagnose specific missing capabilities
2. Synthesize a separate training environment for each capability, with a reward that directly measures that capability being exercised
3. Train a LoRA adapter per capability with GRPO in its isolated environment
4. Route at inference

Each adapter sees a reward that is **dense in its own environment** even though the global task reward was sparse. This avoids the credit-assignment problem entirely — there are no long multi-step trajectories between reward and action at the adapter-training level.

The implication: three complementary axes for making sparse global signals tractable:

| Strategy | Mechanism | Example |
|----------|-----------|---------|
| Enrich the signal | Gather traces, errors, analyses at each step | [sources/meta-harness](../sources/meta-harness.md), [sources/optimize-anything](../sources/optimize-anything.md) (ASI) |
| Redistribute the signal | Broadcast terminal outcome across intermediate steps | [sources/agentflow](../sources/agentflow.md) (Flow-GRPO) |
| Decompose the signal | Split into capability-isolated sub-signals with their own environments | [sources/trace](../sources/trace.md) |

These are not mutually exclusive — a sophisticated system could enrich feedback *within* each isolated environment, for example.

## Credit Assignment as an Alternative to Signal Richness

**AgentFlow** ([sources/agentflow](../sources/agentflow.md)) presents an important counter-case: it uses only a **binary scalar** (correct / incorrect final answer) — no execution traces, no textual gradients, no environmental feedback. Yet it achieves +14.9% on knowledge-intensive benchmarks and +14.0% on GAIA with a 7B model, sometimes beating GPT-4o.

The mechanism that makes sparse scalar feedback work here is **trajectory-level broadcasting**: the terminal reward is assigned to every intermediate decision step in the multi-turn trajectory (via Flow-GRPO). This is not dense reward — the signal itself is still sparse and binary — but the credit assignment ensures that early planner decisions are properly attributed for late-trajectory outcomes.

The implication: **what matters is not just the *richness* of the feedback signal, but the *alignment* between signal and the decision points being optimized.** A sparse signal with correct attribution can outperform a rich signal that arrives only at iteration boundaries.

## Systems That Do Not Use Traces

**EvoX** is notably different: it does not use execution traces at all. Its feedback is purely population-level — diversity metrics, improvement rate, stagnation detection. The outer strategy-evolution loop observes aggregate statistics across the population, not the internals of individual runs. This works because EvoX's optimization target is the *search strategy*, not the solution content — you don't need to know *why* a specific candidate failed, only whether the current strategy is making progress overall.
